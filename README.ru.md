> **Нам нужна ваша поддержка.** Заходите на Discord-сервер — <https://discord.gg/AMDNR> — за
> помощью, с баг-репортами и за тестовыми сборками; каждый отчёт с логом делает следующую сборку лучше.

DLSS 5 Neural Rendering на видеокартах AMD, встроенный в OptiScaler, поэтому он работает в любой
игре на Direct3D 12, которую OptiScaler уже умеет перехватывать. Поверх нейронного прохода: model interleave
для большого прироста FPS, residual composition (остаточная композиция), генерация кадров (FG) XeSS,
разблокированная до 6X (до 10X — по желанию, в играх на D3D12), и FSR Ray Regeneration для игр,
использующих DLSS Ray Reconstruction. С 0.3.5 **AMDNR Anywhere** (preview) приносит Neural Rendering в игры, у которых
нет собственного апскейлера, через AMDNR Launcher, ничего не записывая в папку игры (см. «AMDNR Anywhere»). С 0.3.5.6
в списке апскейлеров есть ещё два экспериментальных варианта от других авторов, включаемых по желанию, — **Model E**
(HelixSR) и **Model L** (d4r); AMDNR Launcher скачивает их из собственных релизов их авторов (см. «Model E и Model L»).

**Discord: <https://discord.gg/AMDNR>** — поддержка, баг-репорты (`#bug-report`), тестовые
сборки.

## AMDNR - Руководство по установке OptiScaler

Установка довольно простая. **В Windows AMDNR Launcher сделает всё это за вас** (см. «AMDNR Launcher»
ниже). Вручную:

### 1. Скачайте файлы

Скачайте эти файлы из последнего релиза на GitHub (<https://github.com/3zwr1/AMD-NR---OptiScaler/releases>;
у 0.3.5.6 тег Alpha0.3.5.6):

* `AMDNR-vX.X.X.zip` (для 0.3.5.6: `AMDNR-v0.3.5.6.zip`), с полным рантаймом lmxxf.
* Для рантайма danielblnc — один zip рантайма: `v0.6.0-Runtime.zip` (рекомендуется; RX 9000, RX 7000 и, при
  установленном HIP SDK от AMD, RX 6000) из Alpha0.3.5.5R4; `v0.5.1-Runtime.zip` (Alpha0.3.5), `v0.5.0-Runtime.zip`
  (Alpha0.3.4.2; в некоторых играх на некоторых видеокартах он может вызывать зависания), `v0.4.3-Runtime.zip`
  (Alpha0.3.4.2 и Alpha0.3.4.1), `v0.4.1-Runtime.zip` и `v0.4.0-Runtime.zip` (Alpha0.3.4.1) по-прежнему принимаются на
  RX 9000 и RX 7000. Рантайм lmxxf входит в `AMDNR-vX.X.X.zip`, и на RX 7000 и RX 9000 zip рантайма ему не нужен; APU
  портативных ПК используют только lmxxf. AMDNR Launcher сам выбирает нужный zip под вашу видеокарту. См. «Что лежит
  в архивах».
* Для Model E и Model L ничего скачивать вручную не нужно: AMDNR Launcher скачивает их из собственных релизов их
  авторов, когда вы их выбираете (см. «Model E и Model L»).

### 2. Распакуйте оба файла

Распакуйте содержимое обоих файлов `.zip`.

### 3. Скопируйте всё в папку игры

Сначала скопируйте все файлы из `AMDNR-vX.X.X` в корневую папку игры — ту же папку, где
лежит `.exe` игры.

Затем сделайте то же самое со всеми файлами из zip рантайма (например, `v0.6.0-Runtime` на RX 9000, RX 7000 и RX 6000).

> **Обновляетесь со старой версии AMDNR?** Скопируйте всё заново с заменой. **Заменяйте эти три файла вместе:**
> `OptiScaler.dll` (замените файл, который вы переименовали, например `dxgi.dll`, новым с тем же именем),
> `LmxxfNrRuntime.dll` и `LmxxfNrRuntime.pak` (440 МБ). Не смешивайте их со старыми копиями: в 0.3.5.6
> `OptiScaler.dll` передаёт `LmxxfNrRuntime.dll` новые данные кадра, а более старый рантайм работает без них. Свой
> `OptiScaler.ini` можно оставить: новые настройки берут значения по умолчанию. Файлы из вашего zip рантайма
> danielblnc остаются как есть (Doctor в лаунчере предложит рекомендуемый для вашей видеокарты). AMDNR Launcher
> делает это за вас: UPDATE ALL или REPAIR / UPDATE у игры с пометкой "Update available" (лаунчер сначала обновляет
> себя).

### 4. Переименуйте OptiScaler.dll

В папке игры найдите:

`OptiScaler.dll`

Переименуйте его в:

`dxgi.dll`

`dxgi.dll` — рекомендуемый вариант.

Если игра не запускается или мод не загружается, попробуйте вместо этого переименовать `OptiScaler.dll`
в одно из этих имён:

* `d3d12.dll`
* `winmm.dll`
* `version.dll`
* `dbghelp.dll`
* `winhttp.dll`
* `wininet.dll`

Пробуйте по одному имени за раз. Не создавайте несколько копий `OptiScaler.dll`. Это имена, под которыми мод
загружается (плюс `OptiScaler.asi` с ASI-загрузчиком); `d3d11.dll` к ним не относится.

> **Resident Evil Requiem (и её демо) требует REFramework.** Это известное требование, а не баг AMDNR: OptiScaler полагается
> на него, чтобы обойти anti-tamper от Capcom ([вики OptiScaler](https://github.com/optiscaler/OptiScaler/wiki/Resident-Evil-9-Requiem)). Без него игра вылетает
> через 15-60 с после запуска ("An unhandled exception occurred"). Положите `dinput8.dll` из архива `REFramework.zip` последней nightly-сборки
> (<https://github.com/praydog/REFramework-nightly/releases>) рядом с `dxgi.dll` и смените клавишу меню REFramework (например, на Delete): его меню тоже открывается по Insert.
> После обновления игры ждите вылетов, пока не обновится REFramework. PRAGMATA, Monster Hunter Wilds и Onimusha, вероятно, тоже его требуют (не подтверждено).

### 5. Запустите игру

`HOME` включает и выключает Neural Rendering прямо во время игры (для обоих рантаймов; небольшое уведомление
показывает On / Off). Переназначить клавишу можно рядом с галочкой Enable на вкладке Neural или в Interface > Keybinds.

Вот и всё.

Запустите игру как обычно и нажмите:

`INSERT`

Откроется меню OptiScaler / AMDNR, где можно настроить мод как вам угодно.

### Если не работает

Если игра так и не запускается ни с одним из имён выше, пожалуйста, сообщите об этом в канале
`#bug-report` в Discord.

К отчёту о проблеме также приложите все файлы `.log`, которые могли появиться в
корневой папке игры.

Эти логи очень важны и помогут нам найти проблему гораздо быстрее.

**Проще всего: Save report.** Если меню открывается, нажмите **Save report** (последняя строка Neural > Diagnostics или первая строка Advanced > Logging). Эта кнопка создаёт
один zip, `AMDNR-report-<exe игры>-<дата>.zip`, в папке игры (на Рабочем столе, если папка игры доступна только для
чтения, иначе в `%TEMP%`) с `report.txt`, логами и ini-файлами, а меню показывает, куда он сохранён. Ваше имя
пользователя Windows и имя ПК заменяются заглушками; имя внутри пути к игре вне `C:\Users\` — нет. Приложите zip в
`#bug-report`. **COLLECT LOGS** в AMDNR Launcher создаёт такой же zip для любой игры, а с 0.3.5.1 после вылета
добавляет в него лог вылета и самый свежий дамп.

> `.exe` обычно лежит не там, куда указывает ярлык. В играх на Unreal он находится в
> `<Game>\Binaries\Win64\`.

### Рантайм lmxxf (0.3.0, опционально)

Второй нейронный рантайм (под лицензией MIT, от lmxxf) может выполнять проход вместо рантайма
danielblnc. На RDNA 4 он работает нативно; на RDNA 3 (RX 7000, Strix Halo) — через RDNA 3-бэкенд AMDNR от 3zwr1,
там медленнее, см. «RX 7000» ниже: начните с NR resolution 70% или ниже. На APU портативных ПК он тоже работает,
экспериментально (см. «APU портативных ПК» ниже). Рядом с игрой ему нужны две вещи:

1. `LmxxfNrRuntime.dll` - в этом архиве, рядом с `OptiScaler.dll` (копируется вместе с остальными файлами).
2. `LmxxfNrRuntime.pak` (440 МБ, входит в zip AMDNR) рядом с `LmxxfNrRuntime.dll` - файлы весов lmxxf,
   модули HIP и HLSL в одном зашифрованном файле с проверкой подлинности. Рантайм открывает его в
   памяти; на диск ничего не распаковывается.

При первом запуске, когда найден установленный рантайм, а выбор ещё не сделан, меню спрашивает, какой
из них использовать (выбор записывается в ini как `[DlssNr] NrBackend = daniel | lmxxf`; сменить его можно
в Neural > Neural runtime, изменение вступит в силу при следующем запуске игры). Правка lmxxf применяется
с опозданием на один кадр и переносится по векторам движения, так что кадр никогда не ждёт нейросеть
(около 14.1 мс времени сети в 1080p на RX 9070 XT). Лог lmxxf — `lmxxf_backend.log` рядом с игрой.

**Совместимость (lmxxf).** Рантайм видит только то, что видит DLSS, поэтому от игры к игре меняется
лишь короткий список: формат цвета и HDR, векторы движения и их масштаб, глубина и её направление,
reactive mask, текстура экспозиции, флаг Reset и то, где стоит проход (до Super Resolution или после
Ray Reconstruction). На данный момент проверено:

| Игра | API / положение | Примечания |
|---|---|---|
| Silent Hill 2 | D3D12, до SR | эталонная игра; учтено, что Unreal выделяет цветовой буфер с паддингом |
| Forza Horizon 6 | D3D12, до SR | |
| Stray | D3D11 через мост D3D12, до SR | |
| GTA V Enhanced | D3D12, до SR, HDR, одноканальная reactive mask | исправлено в 0.3.0: маска читалась как «всё реактивное», и правка так и не применялась |
| Любая игра с Ray Reconstruction | D3D12, после RR (записывается обратно в выходной кадр) | поддерживается с 0.3.0; в играх пока не подтверждено |

Если в игре нет эффекта: в `lmxxf_backend.log` есть строка `lmxxf inputs:` (форматы, размеры,
масштаб движения, направление глубины, маска, экспозиция) и строка `lmxxf stats @N:` каждые 600 кадров
(экспозиция, подаваемая яркость, правка модели, перенесённая правка, keep, среднее по reactive, длина
векторов и доля отброшенных). Приложите лог к отчёту; эти две строки обычно объясняют причину.

Оба рантайма используют одну общую вкладку Neural (см. «Меню» ниже). С 0.3.5.6 настройка, которую активный рантайм
не может выполнить, на этом рантайме скрыта, со счётчиком (её ключ ini продолжает работать). Только у lmxxf: **Full network**, **Output smoothing**
(Quality > More quality options, требует Network history), **Edit detail**, **Edit colour** и **Edge guard** (Image
look > Model strength: усиление мелкой части правки модели, её цвет относительно изменения её яркости и
затухание правки на границах глубины) и ограничение ярких участков в автоэкспозиции. Новое для lmxxf в 0.3.4:
Network output, Encoding, Residual edge fade, Game exposure, Fast mode, показатель пейсинга interleave и
родная маска персонажей модели вместе со Structure intensity и Character structure (каждое
изменение пересобирает сеть: фриз примерно на 1 с).

**Full network** (Neural > Performance, `[DlssNr] LmxxfFullNetwork`, только lmxxf) прогоняет все 71 блок
сети вместо того, чтобы пропускать 42, 43 и 46: чуть точнее, примерно на 0.5 мс медленнее в 1080p
(16.6 -> 17.1 мс на RX 9070 XT, измерено в 0.3.3). По умолчанию выключено.

**Fast mode** (Neural > Performance, `[DlssNr] AmdLmxxfFastMode`, lmxxf) запускает сеть на один уровень размера ниже
(1080 -> 900, 900 -> 720; 720 -> 576 и 576 -> 360 там, где включены малые размеры): примерно на 29% меньше времени сети
в 1080p (RX 9070 XT, измерено вне игры), мелкие детали чуть мягче. **С 0.3.5.6 он по умолчанию включён на RX 7000,
Radeon 8060S / 8050S и APU портативных ПК** и по умолчанию выключен на RX 9000; `false` (или галочка) выключает его,
`true` включает, а галочка показывает, что реально работает. В сборках danielblnc, где есть собственный Fast mode, там тоже
появляется строка Fast mode (`[DlssNr] AmdDanielFastMode`); в рантаймах из архивов рантайма этого релиза его нет,
поэтому строка скрыта.

### RX 7000 (RDNA 3): быстрее благодаря уровням размера сети (новое в 0.3.4)

Сеть lmxxf работает в нескольких фиксированных размерах (уровнях): 720 (1280x720), 900 (1600x900) и 1080
(1920x1080), плюс 576 и 360 (новые, используются на портативных ПК). Уровень стоит одинаково, какую бы его часть
ни заполняла картинка. На RDNA 3 (RX 7000, Radeon 8060S / 8050S и APU портативных ПК) размер NR у lmxxf теперь по
умолчанию подгоняется под уровень: опускается до следующего меньшего уровня, если ближе к нему (дешевле), иначе
увеличивается до заполнения своего уровня (та же нагрузка, чуть больше деталей), но никогда не больше размера
самого кадра.

Время сети на один прогон на RX 7800 XT (измерено тестером с помощью пробы lmxxf; только сеть, среднее по 30
прогонам; время уровня 900 измерено при 1600x900):

| Настройка игры | 0.3.3.2 | 0.3.4 на RX 7000 |
|---|---|---|
| 1440p, FSR Quality (рендер 1706x960), NR 100% | уровень 1080: 73.3 мс | уровень 900: 52.2 мс |
| Рендер 1080p, NR 85% | уровень 1080: 73.2 мс | уровень 900: 52.2 мс |
| Рендер 1080p, NR 70% | уровень 900: 52.2 мс | уровень 720: 34.4 мс |
| Рендер 1080p, NR 80% | уровень 900: 52.2 мс | уровень 900, заполненный: 52.2 мс (больше деталей) |
| Рендер 1080p, NR 100% | уровень 1080: 73.2 мс | без изменений |

- В игре выигрыш на показанный кадр меньше: с Model interleave сеть работает через кадр, а у игры есть своя
  нагрузка. В игре пока не измерено.
- Сеть видит чуть меньшую картинку (в 1440p Quality примерно на 6% меньше пикселей по каждой стороне), поэтому
  мелкие детали могут стать чуть мягче. `[DlssNr] AmdLmxxfTierSnap=false` возвращает размеры 0.3.3.2. С 0.3.5.2
  RX 9000 тоже подгоняют размер по умолчанию.
- **RX 9000:** `[DlssNr] AmdLmxxfTierSnap` (там включено по умолчанию с 0.3.5.2; до этого — по желанию) переводит
  размер NR у lmxxf на размер сети при каждом разрешении рендера: одни размеры опускаются на уровень ниже (1440p FSR
  Quality, 1707x960 -> размер 900: сеть 14.08 -> 9.96 мс за прогон на RX 9070 XT, измерено вне игры, картинка чуть
  мягче), другие растут внутри своего уровня (80% от рендера 1080p -> 1600x900: та же нагрузка, чуть больше деталей).
  `false` сохраняет размеры 0.3.3.2.
- Начните с NR resolution 70% или ниже (уровень 720 при рендере 1080p; пресет Performance — это 70%). Нагрузка
  рядом с NR resolution считается по уровню, на котором работает сеть; подсказка к ней называет уровень.
- **0.3.5: примерно на 10 процентов меньше времени сети на RX 7000**, картинка побитово та же: набор модулей 0.3.5 в
  `LmxxfNrRuntime.pak` (измерено и проверено по хешу тестером на RX 7800 XT; таблица выше — для 0.3.4).
- **0.3.5 на RX 9000: lmxxf 0.37 от Kien (MIT) включён по умолчанию** — примерно на 20 процентов меньше времени сети
  на RX 9070 XT при размере 1080 (14.0 -> около 11.3 мс, измерено вне игры; картинка не совпадает побитово с 0.3.4.2).
  На RX 9060 / 9060 XT он тоже включён, вместе с ядрами c32w и FastK, как эксперимент (на этой видеокарте ещё не
  запускался). Выключатели: `[DlssNr] AmdLmxxfL37=false`, `AmdLmxxfC32w=false`, `AmdLmxxfFastK=false`.
- **С 0.3.5.3 набор по умолчанию на RX 9000 — lmxxf 0.41 от Kien (MIT)** (`[DlssNr] AmdLmxxfL41=false` его
  выключает); с 0.3.5.6 пункт Neural runtime называет набор, который реально работает. **С 0.3.5.5R4 RX 7000 и
  портативные ПК класса Z1 Extreme работают на более новых наборах ядер**, картинка побитово та же (проверено по хешу
  на машинах тестеров).
- **0.3.5.6: Fast mode по умолчанию включён на RDNA 3** (RX 7000, Radeon 8060S / 8050S и APU портативных ПК): сеть
  работает на один размер ниже того, который выбрал бы размер рендера (рендер 1080p работает в размере 900), что
  занимает меньше времени на кадр, а мелкие детали становятся чуть мягче. На RX 9000 ничего не изменилось (выключен).
  Отчётов из игр с этих видеокарт пока нет: пожалуйста, пришлите свой. `[DlssNr] AmdLmxxfFastMode=false` (или
  галочка Fast mode) выключает его.

### APU портативных ПК (экспериментально, новое в 0.3.4)

lmxxf работает на APU портативных ПК с 12 и более вычислительными блоками через RDNA 3-бэкенд AMDNR от 3zwr1:
**Z1 Extreme, Z2 и Radeon 780M** (gfx1103), **Z2 Extreme, Radeon 890M и 880M** (gfx1150). Это экспериментально и медленно. Строка Neural runtime показывает "experimental" после благодарности за
RDNA 3-бэкенд.
Первые результаты тестера (ROG Ally, Z1 Extreme): проба lmxxf вне игры, 54.7 мс на прогон сети в размере 360p,
110.9 мс в 576p; в игре, прогон одного тестера (Shadow of the Tomb Raider, 1280x720 с XeSS, пресет Handheld) в среднем 62 мс на прогон
сети в 360p при модели на каждом 4-м кадре, около 29 fps с включённым NR. **0.3.5 снимает с этих чисел примерно
10 процентов на классе Z1 Extreme** (Z1 Extreme, Z2, Radeon 780M: около 50 мс в 360p, около 105 мс в 576p, картинка
побитово та же, проверено по хешу тестером); модули для Z2 Extreme / 890M / 880M не изменились.

- **Не поддерживаются:** Z1 и Radeon 740M (4 вычислительных блока), Radeon 760M (8), Radeon 860M / 840M. Рантайм
  danielblnc на APU портативных ПК не работает. Десктопные видеокарты RX 6000 (RDNA 2) работают с рантаймом
  danielblnc 0.6.0 (см. «Требования»; lmxxf на них запланирован на 0.3.6); Steam Deck и другие APU на RDNA 2 не
  поддерживаются.
- **Что он делает сам** (только пока в вашем ini нет своего значения): размер сети ограничен 576 (1024x576; так с
  0.3.5.5R3, раньше было 360p), а с 0.3.5.6 по умолчанию включён Fast mode, поэтому сеть работает на один размер ниже,
  в 360p (640x360); модель — каждый 4-й кадр (Model interleave; не сохраняется). С 0.3.5.5R3 ваши Neural passes
  сохраняются (раньше их удерживали на 1); нагрузка NR учитывает их в своей цене.
- **Скорость, честно:** Для
  сравнения: RX 7800 XT (60 вычислительных блоков) нужно 34.4 мс на прогон сети в размере 720; у этих чипов их от
  12 до 16, и частоты ниже. Ждите сильного падения FPS даже в 360p с моделью каждый 4-й кадр, немного гостинга из-за
  длинного interleave и более мягкой картинки, чем на десктопной видеокарте. Нагрузка NR в конце строки состояния
  вкладки Neural (и в Diagnostics) показывает реальное число на вашем устройстве.
- **Настройки:**
  - Чётче, но медленнее: `[DlssNr] AmdLmxxfFastMode=false` (размер сети 1024x576; `[DlssNr] AmdLmxxfTierCap=360`
    удерживает самый маленький размер даже с выключенным Fast mode).
  - С включённым Fast mode рендер 720p или 800p при NR resolution 100% уже работает в размере 360p, так что более
    низкая NR resolution не делает дешевле.
  - Model interleave в положении Off сохраняется как `[DlssNr] AmdInterleave=1` (тоже выключено), чтобы значение
    по умолчанию для портативного ПК не вернулось при следующем запуске. Чтобы выключить вручную, пишите 1, а не 0.
  - Preset > **Handheld** (с 0.3.5.1) задаёт NR resolution 80%, Dynamic NR выключен, модель на каждом 4-м кадре с Edit accumulation, 1 Neural pass, Full network включён, Fast mode включён и Before upscaling, плюс собственные значения облика (Residual limit 0.32, Temporal stability 0.70, Sharpening 0.10, Output smoothing 0.65 и ещё несколько; подсказка кнопки перечисляет их все). Кнопка есть только на этих APU; Quality, Balanced и Performance здесь тоже оставляют размер сети для портативных ПК (меню об этом сообщает).
- **FSR 4:** FSR 4 (INT8) доступен как экспериментальная опция на портативных ПК с RDNA 3 (вкладка Upscaling); не проверен AMD.
  Флажок **FSR 4 (INT8) - Experimental on this GPU (restart)** записывает `[FSR] Fsr4ForceModel=2`; сам он никогда не включается
  (при `Dx12Upscaler=auto` апскейлер — XeSS). Около 1,5-3 мс на кадр на Z1 Extreme (оценка); с NR —
  FSR 4 или размер 576, но не оба сразу.
- **Shadow of the Tomb Raider** (и игры, которые создают D3D12-устройство дважды) больше не вылетает при запуске
  апскейлера (исправлено в 0.3.4).
- **Драйвер:** используйте фирменный драйвер AMD Adrenalin. lmxxf нужен HIP (`amdhip64_7.dll`), которого нет в
  некоторых драйверах производителей портативных ПК; тогда `amd_bridge.log` сообщает, что HIP недоступен.
- **Движение с Model interleave (исправлено в 0.3.5):** перенесённая правка пропадала, как только вы начинали
  двигаться («при движении эффект пропадает»): под Model interleave сеть работает на кадрах разной длительности, а
  защита переноса предполагала равные кадры. Теперь она читает векторы предыдущего кадра с длительностью текущего
  кадра (оба рантайма).
- **Используйте файлы одного релиза вместе:** заменяйте `OptiScaler.dll`, `LmxxfNrRuntime.dll` и
  `LmxxfNrRuntime.pak` вместе; рантайм отказывается работать на портативном ПК, если
  `OptiScaler.dll` старее 0.3.4 ("this handheld needs OptiScaler.dll 0.3.4 or newer").
- **Тестерам с портативным ПК:** попросите в Discord тестовый набор для портативных ПК (`handheld-test.zip`). Его
  `run_probe.bat` измеряет сеть на вашем устройстве и записывает `handheld_result.txt` (ваше имя пользователя
  Windows скрывается).

## AMDNR Anywhere (preview, новое в 0.3.5)

**Что это.** Neural Rendering для игр, в которых нет собственного DLSS, XeSS или FSR 2, — и в папку игры ничего не
записывается. AMDNR работает внутри хоста захвата окна: хост захватывает окно игры, масштабирует его под ваш экран,
а Neural Rendering работает на захваченной картинке; наше меню рисуется внутри хоста (ваша клавиша
меню, по умолчанию `INSERT`) со своей вкладкой **Anywhere**. Хост —
**Magpie by Blinue, experimental fork by SAOG0721 (GPL-3.0)** в собственной сборке AMDNR: его `Magpie.exe` пересобран с изменениями AMDNR (предложение исходного кода, один diff от тега форка и параметры сборки лежат рядом, в `Anywhere-host-source/`), а в пакете нет файлов NVIDIA. AMDNR Launcher скачивает его из релиза AMDNR на GitHub (около 130 МБ для 0.3.5.6, один раз для каждой версии хоста).

**Как пользоваться.** В AMDNR Launcher у игры без апскейлера вместо INSTALL показана кнопка **PLAY ANYWHERE**.
Нажмите её: лаунчер скачивает хост (в первый раз), запускает игру, и хост захватывает её окно. Запускайте игру **в
окне или в окне без рамки**, не в эксклюзивном полноэкранном режиме, и нажмите свою клавишу меню, чтобы открыть меню
AMDNR внутри хоста. Игра с собственным апскейлером остаётся на обычном пути INSTALL: Anywhere — для игр, у которых
его нет.

**Настройки хоста находятся в меню**, в Host settings на вкладке Anywhere (у лаунчера тоже есть своя панель, см.
ниже): размер окна игры
(720p / 900p / 1080p — совет, что выставить в игре; хост захватывает любое окно, которое откроет игра), список этапов
(V1: один проход FSR 3 на экран; V2: FSR 3 в 1x, затем проход заполнения), уровень NR (Auto / 720 / 900 / 1080), VRR,
пейсинг кадров и **частота кадров хоста** (Default = частота обновления вашего дисплея, не больше 60; Auto = частота,
которую сеть выдерживала в прошлой игровой сессии; от 30 до 120; Display refresh = без ограничения). Они применяются
при **следующем** PLAY ANYWHERE, а лаунчер показывает рядом с кнопкой сводку только для чтения. В собственном
`OptiScaler.ini` хоста это `[DlssNr] AnywhereWindow`, `AnywhereEffect`, `AnywhereNrTier`, `AnywhereVrr`,
`AnywherePacing` и `AnywhereHostFps`. Ограничьте и саму игру, её собственным лимитером, на 60-90 fps: хост может
показать только кадры, которые нарисовала игра, и каждый кадр хоста один раз прогоняет сеть. **С AMDNR Launcher
0.3.5.25 у лаунчера тоже есть панель настроек Anywhere** (рантайм NR, Neural passes, нейронный размер, FSR Auto /
FSR 4 / FSR 3 / Off — Off сохраняет NR —, генерация кадров (экспериментально), движение для апскейлинга, резкость и
Model E / Model L (экспериментально; вместе с Neural Rendering внутри Anywhere они ещё тестируются)); она записывает
тот же ini хоста и применяется при следующем PLAY ANYWHERE.

**Чего хост не может дать сети.** У захваченного окна нет собственной глубины, векторов движения, джиттера и
экспозиции; движение хост оценивает сам. Поэтому вкладка Anywhere называет, что оценивается; строки вкладки Neural,
которые там не могут действовать, скрыты или отклонены с указанием причины (Ray Regeneration, Screen GI и Model
interleave — он тратил бы перенесённую правку на оценённое движение); а строка состояния на странице Anywhere
сообщает, когда сеть выходит за бюджет кадра хоста и что снизить. **Окно игры 1920x1080 или меньше — случай точного
соответствия пикселей:** большее окно сначала уменьшается до потолка сети и затем масштабируется обратно, и страница
об этом сообщает, указывая долю пикселей экрана, которую видела сеть. Строка NR resolution показывает реальный размер
сети внутри хоста.

**Статус: preview.** В этом релизе — только RX 9000 (RDNA 4); RX 7000 — после проверки на них. В быстром движении
может оставаться лёгкое мерцание или подёргивание (снизьте уровень NR до 720, ограничьте игру на 60-90 fps, оставьте
Model interleave выключенным — хост его отклоняет). Хост захвата — собственная сборка AMDNR, он скачивается из релиза AMDNR на GitHub. Отчёты: zip **Save report** из меню внутри хоста (его заголовок называет масштабируемую игру) или COLLECT LOGS
в лаунчере.

## Model E и Model L (экспериментально, по желанию, новое в 0.3.5.6)

Ещё два варианта Super Resolution (апскейлера) рядом с FSR и XeSS. **Это не работа AMDNR и не модели AMDNR, и ни
одного из них нет в zip AMDNR.** Когда вы выбираете один из них в AMDNR Launcher (GAME SETTINGS игры > **SR model**:
Auto / Model E / Model L), лаунчер один раз показывает сведения об этой модели (disclosure), просит вас их принять и
скачивает файлы из собственного релиза автора с проверкой по хешу. AMDNR не размещает и не распространяет ни их
файлы, ни какие-либо файлы NVIDIA. Оба экспериментальные: возможны поломки, и если что-то пошло не так, пришлите
отчёт. **Auto** оставляет обычный путь игры (и убирает файлы Model L из папки игры).

**Model E — HelixSR от lonewolf0622** (<https://github.com/lonewolf0622/HelixSR>), под его собственной лицензией.
- HelixSR собирает свою сеть на вашем ПК из файла DLSS от NVIDIA, который лаунчер скачивает с собственного GitHub
  NVIDIA (или берёт из вашей игры); то, что он собирает, остаётся на вашем ПК.
- В игре: Upscaling > **HelixSR (Model E) - restart required** (игры на D3D12; `[Upscalers] FfxSRProvider=helix_e`).
  Вступает в силу при следующем запуске игры.
- Работает с **обоими** рантаймами NR, danielblnc и lmxxf. В наших тестах он работал в игре на RX 9070 XT.

**Model L — d4r от countervolts** (<https://github.com/countervolts/d4r>), под собственной лицензией d4r.
- **Что это:** d4r запускает **рантайм DLSS от NVIDIA, по EULA NVIDIA, через ZLUDA / HIP** на видеокарте AMD.
  Лаунчер скачивает пакет d4r из собственного релиза d4r на GitHub и раскладывает его в папке игры как `AMDNR-SR-L\`;
  AMDNR не размещает и не распространяет никаких файлов NVIDIA. **Автор d4r не проверял его в Windows.**
- **Только RX 9070 / RX 9070 XT** (проверено на RX 9070 XT; RX 9060 XT и более старые видеокарты получают отказ) и в
  игре — **только игры на D3D12**.
- **Он работает с рантаймом lmxxf или с выключенным Neural Rendering. Рантайм danielblnc работает в паре с Model E:**
  когда рантайм NR — danielblnc, строка Model L показана серой ("Model L runs with the lmxxf runtime (or with Neural
  Rendering off); danielblnc's runtime pairs with Model E. Pick lmxxf under Neural Rendering first." — «Model L
  работает с рантаймом lmxxf (или с выключенным Neural Rendering); рантайм danielblnc работает в паре с Model E.
  Сначала выберите lmxxf в разделе Neural Rendering.»), а игра, запущенная с обоими, вместо него использует ваш
  апскейлер FSR.
- В игре: Upscaling > **Model L (d4r) - restart required**, показан серым с причиной, когда здесь он работать не может
  (игра не на D3D12, не подготовлен в лаунчере, видеокарта не RX 9070 / 9070 XT, рантайм danielblnc или ещё нужен
  перезапуск). Выбор записывает `[DlssNr] AmdSrModel=L` (выбор другого апскейлера удаляет эту строку); вступает в силу
  при следующем запуске игры.
- **Экспериментально:** его скорость ещё не настроена, и он может работать намного медленнее FSR. Если он не может
  запуститься, игра должна оставить ваш апскейлер FSR (не FSR 2.1.2), а `OptiScaler.log` объясняет причину в строке
  `[MODELL`.

Внутри **AMDNR Anywhere** оба предлагаются в настройках Anywhere лаунчера; вместе с Neural Rendering там они ещё
тестируются.

## Известные ограничения (0.3.5.6)

- **Гостинг с lmxxf уменьшен, но не устранён:** за быстро движущимися объектами всё ещё может тянуться более короткий
  шлейф.
- **Fast mode на RX 7000 и портативных ПК** — новое значение по умолчанию, отчётов из игр пока нет: пожалуйста,
  пришлите свой. `[DlssNr] AmdLmxxfFastMode=false` возвращает прежний размер сети.
- **Full Model Look после апскейлинга стоит дороже**, потому что сеть получает картинку размером с экран. Там, где
  проверка нагрузки или запись TDR этой игры говорят, что видеокарта не может себе этого позволить, он выполняется до
  апскейлинга, и строка состояния Neural об этом сообщает; ваш собственный `[DlssNr] AmdPlacement=pre` тоже удерживает
  его до апскейлинга (об этом сообщается один раз: снова выберите Full Model Look в NR style или удалите эту строку).
- **Откат к FSR 2.2:** в некоторых играх на D3D11 и Vulkan неудавшийся апскейлер всё ещё может откатиться к FSR 2.2.
- **Model L** — только RX 9070 / RX 9070 XT и D3D12, не работает в паре с рантаймом danielblnc, экспериментальный и
  может быть намного медленнее FSR; автор d4r не проверял его в Windows.
- **Model E и Model L внутри AMDNR Anywhere** вместе с Neural Rendering ещё тестируются.
- **danielblnc на RX 7000:** режим того же кадра в его рантайме по своему устройству занимает много времени на кадр на
  RDNA 3; используйте там lmxxf.
- **Linux / Proton:** Neural Rendering там не работает (см. ниже).

## Linux / Proton (Steam Deck, настольный Linux)

AMDNR работает под Proton и Wine как сборка OptiScaler. **Neural Rendering в Linux не работает (только Windows):**
обоим рантаймам NR нужен HIP из драйвера AMD для Windows, а Proton и Wine его не предоставляют. Если включить NR под
Proton, NR не запустится, и с 0.3.5 вкладка Neural и отчёт об этом сообщают (вместо "Idle"). Это ожидаемо, а не вылет и не сломанная установка. AMDNR
Launcher — программа для Windows, которая может работать под Proton (экспериментально, нами пока не проверено, см.
ниже); установить AMDNR вручную можно и без него.

**Что работает:** апскейлеры FSR (FSR 3.1, а также FSR 4 на видеокартах и драйверах, которые его поддерживают), меню
(`INSERT`) и **Save report**. Игрок подтвердил в Steam Proton (RX 9070 XT, vkd3d-proton, Resident Evil Requiem), что
игра запускается, меню открывается и принимает ввод мыши, а Save report работает, в том числе с включённой генерацией
кадров.

**Ray Regeneration и генерация кадров:**
- Известная проблема: Ray Regeneration может показывать розовые / пурпурные пятна под Proton; повышение резкости по умолчанию там теперь выключено, но если вы всё равно их видите, используйте обычный FSR (FSR 4 на RX 9000) и отправьте Save report.
  Под Proton AMDNR не добавляет резкость после Ray Regeneration, когда игра не передаёт свою (в Windows добавляет
  0.25): Image > Sharpness показывает "RR default 0 (off on Proton)", а Override по-прежнему задаёт ваше собственное
  значение.
- **Генерация кадров** теперь включается без вылета, но счётчики FPS считают и сгенерированные кадры: при ограничении
  60 fps или V-Sync на 60 Гц это 30 настоящих кадров, и выглядит это как 30. Пока оставьте её выключенной под Proton
  (`[FrameGen] FGOutput=nofg`) или включайте, только если игра без неё выдаёт около 60 fps, на экране с частотой выше
  60 Гц.
- **Игры на Vulkan** (игры на RTX Remix, id Tech 8), под Proton так же, как в Windows: на Ray Reconstruction и
  собственную генерацию кадров AMDNR ответ — "not supported", так задумано (денойзер работает на D3D12, а буферы
  трассировки лучей остаются на устройстве Vulkan); с 0.3.5 вкладки Ray Regeneration и Frame Gen говорят об этом,
  вместо того чтобы просить вас включить их в игре, где они серые. DLSS super resolution работает через мост.
- С 0.3.5 `[Spoofing] Dxgi=true` под Proton (путь обновления до FSR 4) больше не даёт сбой при запуске.

**Требования:** актуальный Proton или Wine (проверено: Proton 11, то есть Wine 11), игра на vkd3d-proton (D3D12) или
DXVK (D3D11) — так Proton работает по умолчанию. Более старые версии не проверялись.

**AMDNR Launcher в Linux (экспериментально, нами пока не проверено).** Лаунчер — та же программа для Windows,
`AMDNR-Launcher.exe` (автономная: .NET и другие среды выполнения устанавливать не нужно). Под Wine / Proton он
распознаёт Wine и показывает уведомление о том, что делать. Он также ищет вашу библиотеку Steam в Linux через диск
`Z:` в Wine (`~/.steam/steam` и `~/.local/share/Steam`, а также папки библиотек из `libraryfolders.vdf`). Сами мы
это ещё не проверяли: если попробуете, сообщите нам в Discord, работает ли это. Как попробовать:

1. В Steam добавьте `AMDNR-Launcher.exe` как стороннюю игру (**Games > Add a Non-Steam Game to My Library**; в
   русском Steam: «Игры > Добавить стороннюю игру в мою библиотеку»).
2. В его **Properties > Compatibility** (в русском Steam: «Свойства > Совместимость») принудительно выберите версию
   Proton (Proton Experimental), затем запустите его из Steam.
3. Если игры нет в **LIBRARY** (БИБЛИОТЕКА), нажмите **ADD** (ДОБАВИТЬ) и выберите папку игры (ваши папки Linux
   находятся на диске `Z:`); если лаунчер выбрал не тот `.exe`, используйте **CHOOSE GAME .EXE**
   (ВЫБРАТЬ .EXE ИГРЫ).
4. Выберите игру и нажмите **INSTALL** (УСТАНОВИТЬ).
5. В **Properties > General > Launch Options** игры введите `WINEDLLOVERRIDES="dxgi=n,b" %command%` (если лаунчер
   использовал для игры другое имя DLL, подставьте его вместо `dxgi`), затем выполните шаги 5 и 6 установки вручную
   ниже (запускайте игру из Steam; кнопка **PLAY** в лаунчере под Wine / Proton отключена).

**Установка вручную** (без лаунчера):

1. Скачайте `AMDNR-vX.X.X.zip` со страницы релизов (для 0.3.5.6: `AMDNR-v0.3.5.6.zip`). Zip-архивы рантайма
   danielblnc (`v0.6.0-Runtime.zip` и остальные) нужны только для Neural Rendering, поэтому в Linux они не нужны
   (если скопировать один из них, вреда не будет).
2. Распакуйте zip и скопируйте всё в папку игры, рядом с `.exe` игры.
3. Переименуйте `OptiScaler.dll` в `dxgi.dll`.
4. В Steam откройте **Properties > General > Launch Options** игры (в русском Steam: «Свойства > Общие > Параметры
   запуска») и введите:

   ```
   WINEDLLOVERRIDES="dxgi=n,b" %command%
   ```

   Это указывает Wine загружать `dxgi.dll` из папки игры вместо своей; без этого AMDNR не загружается.
   Если вы выбрали другое имя (например, `winmm.dll` или `version.dll`), подставьте его вместо `dxgi`, например
   `WINEDLLOVERRIDES="winmm=n,b" %command%`. Lutris, Heroic и Bottles: добавьте такое же переопределение (`dxgi` =
   `native,builtin`) в настройках DLL overrides или переменных окружения раннера.
5. В `OptiScaler.ini` задайте `[FrameGen] FGOutput=nofg` (генерация кадров выключена, см. выше).
6. Запустите игру и нажмите `INSERT`, чтобы открыть меню. Настройте апскейлер там.

**Меню.** В 0.3.4 при включённой генерации кадров меню могло открываться, не принимая ввод с мыши и клавиатуры, или
не открываться вовсе. 0.3.4.1 привязывает меню к окну игры; игрок подтвердил под Proton, что меню открывается и
принимает ввод мыши, в том числе с включённой генерацией кадров. Если на вашей системе это всё же происходит, AMDNR
показывает предупреждение "Menu window lost". Тогда в `OptiScaler.ini` задайте `[FrameGen] FGOutput=nofg`; если меню
всё равно не реагирует, задайте также `[Menu] OverlayMenu=false` (классическое меню, которое не зависит от окна
оверлея).

**HDR.** AMDNR не включает HDR под Proton. HDR зависит от настройки вашего Proton и рабочего стола: нужны сборка Proton с
поддержкой HDR и сессия, которая умеет выводить HDR (например, gamescope или рабочий стол Wayland с включённым HDR).
Если HDR работает в игре без AMDNR, он продолжит работать и с AMDNR; если опция HDR в игре серая (недоступна), решение
— в настройке Proton или рабочего стола.

**Как сообщить о проблеме в Linux:** используйте кнопку **Save report** в меню (оставьте `[Log] LogToFile=true`,
значение по умолчанию, чтобы в отчёт попал лог этой сессии); отчёт показывает, работала ли игра под Wine/Proton,
vkd3d-proton или DXVK. Пожалуйста, укажите ваш дистрибутив, видеокарту, версию Mesa и версию Proton.

## Требования

- Windows 10 или 11 (64-бит) для Neural Rendering. AMDNR Launcher — программа для Windows, которая может работать
  под Proton (экспериментально, нами пока не проверено). Под Linux / Proton AMDNR работает как сборка OptiScaler без
  NR (см. «Linux / Proton»).
- Видеокарта AMD с AMD Software: Adrenalin Edition 26.9.1 или новее. Нейронный рантайм использует HIP через драйвер; ни HIP
  SDK, ни режим разработчика не нужны (кроме RX 6000, см. ниже). По чипам:
  - RX 9000 (RDNA 4): оба рантайма.
  - RX 7000 (RDNA 3, десктопные и мобильные): оба рантайма - lmxxf через RDNA 3-бэкенд AMDNR, медленнее, чем на
    RDNA 4 (уровни размера сети и, с 0.3.5.6, Fast mode включены по умолчанию, см. выше).
  - Strix Halo (Radeon 8060S / 8050S): lmxxf.
  - APU портативных ПК с 12+ вычислительными блоками (Z1 Extreme / Z2 / 780M, Z2 Extreme / 890M / 880M): lmxxf,
    экспериментально и медленно. Z1 (4 CU), 760M / 740M и 860M / 840M: не поддерживаются.
  - RX 6000 (RDNA 2, десктопные): рантайм danielblnc 0.6.0 (`v0.6.0-Runtime.zip`) с установленным HIP SDK от AMD
    (HIP 7.2), который кладёт нужный RX 6000 рантайм HIP в собственную папку (AMDNR ищет его там); lmxxf на RX 6000
    пока не работает (запланирован на 0.3.6). Steam Deck и APU на RDNA 2: не поддерживаются (для Neural Rendering;
    об апскейлерах под Proton см. «Linux / Proton»).

  Вкладка Neural показывает, что может запустить ваша видеокарта (наведите курсор на пункты рантаймов или
  посмотрите строку GPU в Diagnostics).
- **AMDNR Anywhere** (preview): Windows, видеокарта RX 9000 (RDNA 4) в этом релизе и AMDNR Launcher, который
  скачивает хост захвата; игра работает в окне или в окне без рамки. См. «AMDNR Anywhere».
- **Model E / Model L** (экспериментально, по желанию): AMDNR Launcher, который их скачивает, и игра на D3D12; для
  Model L также нужны RX 9070 / RX 9070 XT и рантайм lmxxf (или выключенный Neural Rendering). См. «Model E и Model L».
- Игра на Direct3D 12, Direct3D 11 или Vulkan. Сам нейронный путь AMD работает на D3D12; игры на D3D11 и
  Vulkan попадают в него через мост D3D12 от OptiScaler, а значит, апскейлер должен быть одним из
  бэкендов "w/Dx12" (`ffx_12`). Оставьте `Dx11Upscaler` / `VulkanUpscaler` в значении `auto`,
  и эта сборка сама выберет его, когда нейронный рендеринг включён. При включённом Neural Rendering список Upscaling называет их "... w/Dx12 - Neural".
- Около 2 ГБ свободной VRAM при разрешениях рендера класса 1080p.

**AMDNR-vX.X.X.zip**

| Файл | Что это |
|---|---|
| `OptiScaler.dll` | OptiScaler с AMD-бэкендом DLSS-NR (AMDNR 0.3.5.6). Переименуйте его, как сказано в руководстве. |
| `OptiScaler.ini` | Настройки. Neural Rendering включён; логирование включено, чтобы к баг-репорту было что приложить. |

## Настройки, которые стоит знать

Откройте вкладку **Neural**. Значения по умолчанию — это последняя проверенная конфигурация, поэтому
разумный первый шаг — менять что-то одно за раз.

- **NR style** (вверху вкладки Neural, `[DlssNr] AmdNrLook = auto | 0 | 1`, оба рантайма) — первые три пункта —
  это целые облики. **Full Model Look** (`auto`, по умолчанию с 0.3.5.6): сеть облика NVIDIA look (Style 0, все 71
  блок) с более сильными настройками модели — Structure intensity 2 на обоих рантаймах, Edit detail 1.5 и Edit colour
  1.25 на lmxxf, — без residual limit и edge guard, Temporal stability 0.5, а output smoothing, история сети и
  остальные защиты стабильности остаются включёнными; он запрашивает Neural placement After upscaling, пока вы не
  задали размещение сами (см. Neural placement ниже). **NVIDIA look** (`0`, по умолчанию с 0.3.5.3 по 0.3.5.5R4):
  ближе всего к собственному выводу NVIDIA, Before upscaling. **AMDNR soft** (`1`): прежний облик AMDNR, мягче и
  стабильнее. Облик подставляет свои значения, только пока вы не задали эти настройки сами, а под Model interleave
  защиты сохраняют прежние значения. Выбор облика в выпадающем списке также записывает его Neural placement (Full
  Model Look: After upscaling; два других: Before) и Full network как ваши собственные значения. Четыре именованных
  стиля после них задают свои ползунки поверх того облика, который работает.
- **NR resolution** — главный рычаг баланса между качеством и нагрузкой. Ниже 100% модель работает с картинкой
  меньшего размера, и на кадр полного разрешения переносится только её *коррекция*, поэтому
  кадр сохраняет собственную детализацию. Выше 100% нагрузка растёт квадратично (150% — это 2.25x, 200% — 4x). С
  0.3.5.6 ползунок идёт от 25% до 200% на обоих рантаймах (раньше он останавливался на 150%); сеть lmxxf
  по-прежнему ограничена 1920x1080, и строка сообщает об этом, когда упирается именно в этот предел. Ползунок
  двигается с шагом 5%: каждый новый размер NR может удерживать VRAM до перезапуска игры, поэтому
  перезапускайте игру после множества изменений.
  Нагрузка рядом с ним показывает 1.00x при 100%; под lmxxf это цена уровня размера сети, на котором он работает
  (подсказка называет уровень). Кнопки Preset ставят его на 100 / 85 / 70%.
- **Neural placement** (Neural > Performance, `[DlssNr] AmdPlacement = pre | post`, новое в 0.3.5, оба рантайма) —
  где выполняется нейронный проход. `pre` (собственное значение ключа по умолчанию; так работали все сборки до
  0.3.5.6) правит картинку в разрешении рендера, которую апскейлер вот-вот прочитает. `post` вместо этого правит
  готовую картинку апскейлера в разрешении экрана: чётче, потому что апскейлер больше не фильтрует правку повторно, и
  дороже — на lmxxf сеть работает в размере экрана вплоть до своего потолка 1920x1080, так что экран 1080p платит за
  верхний уровень при любой NR resolution, а экран 1440p или 4K получает правку в 1080 строк, поднятую обратно до его
  размера (у danielblnc такого потолка нет, поэтому `post` обходится ему дороже); чуть менее снисходительно в движении,
  и HUD попадает в правку, если игра накладывает его до апскейлинга. **С 0.3.5.6, пока строка пуста или равна `auto`,
  Full Model Look по умолчанию запрашивает `post` на любой видеокарте**; проверка нагрузки, запись TDR этой игры и
  защита от TDR во время игры оценивают его цену и возвращают его к `pre` на эту сессию там, где видеокарта не может
  себе этого позволить (строка состояния Neural и `amd_bridge.log` говорят почему). `pre`, заданный вами самими
  (строкой меню, пресетом Handheld или лаунчером), удерживает облик до апскейлинга; строка состояния об этом сообщает,
  а повторный выбор Full Model Look в NR style записывает `post`. Отклоняется (возврат к `pre`, одна строка в
  `amd_bridge.log`) внутри AMDNR Anywhere, в режиме финального изображения (final image) и после того, как в игре
  уже работал Ray Regeneration. Пока работает `post`, строка NR resolution показывает оба размера.
- **Residual strength** — какая доля правки модели применяется; выше 1 правка усиливается. Именно эта
  настройка сильнее всего меняет картинку.
- **Residual limit** — потолок того, насколько сильно может измениться один пиксель. Появляются пятна — **уменьшите** его.
- **Model interleave** — запускает модель через кадр ради большого прироста FPS.
  Пропущенные кадры заполняет **Interleave preset**; по умолчанию стоит *Edit accumulation* (пресет 10,
  оба рантайма): каждый кадр — это картинка самого этого кадра плюс переносимая моделью правка, так что
  никакая прежняя картинка не удерживается. *Guided fill v2* (пресет 6, danielblnc) и *Classic carry*
  (lmxxf) — более старые способы заполнения. Пейсинг двух типов кадров автоматический на danielblnc и выключен на
  lmxxf (`[DlssNr] AmdInterleavePacing` от 0 до 1 выравнивает оба, ценой части FPS); бледная строка под пресетом
  показывает замер. Adaptive interleave в этой сборке отключён.
- **Neural passes** — 2 и 3 накладывают модель несколько раз, с убывающей отдачей. Под lmxxf
  история сети остаётся за первым проходом; дополнительные проходы — только пространственное уточнение.
  danielblnc в играх на Vulkan выполняет 1 проход (об этом говорит подсказка под ползунком).
- **Refine passes** (Neural > Performance, `[DlssNr] AmdRefineMode = full | refine`, только danielblnc, новое в
  0.3.5.6) — собственный режим проходов AMDNR. *Full* (по умолчанию) выполняет каждый проход в полном размере.
  *Refine* выполняет проход 1 в полном размере, а проходы 2 и 3 — на один размер сети меньше, по ответу предыдущего
  прохода, и затем поднимает их правку обратно на картинку полного размера: все проходы по-прежнему выполняются, но
  дополнительные стоят меньше. При 1 проходе эффекта нет. Рантайм lmxxf собирает один размер сети на сессию, поэтому
  выполняет Refine как Full, и там эта строка скрыта.
- **Colour composition** (Neural > Image look, оба рантайма) — *Classic* (по умолчанию) даёт ту картинку,
  что была у вас раньше. *RenoDX (experimental)* выполняет цветовую композицию RenoDX после модели, как
  это делает путь NVIDIA: Composition detail и colour, двусторонний **Highlight guard** (2x по умолчанию),
  который ограничивает ответ модели относительно оригинала, и необязательные настройки кожи / окружения.
  На display-referred (SDR) кадре, с Network output или с Encoding sRGB / Gamma 2.2 этот режим откатывается к
  Classic на обоих рантаймах; пометка в меню тогда предлагает кнопку, которая убирает помеху. Стили NR и пресеты
  его не трогают.
- **Native character mask** (Image look > Model strength, `[DlssNr] AutoMask`, по умолчанию включена) —
  собственная обработка лиц и кожи моделью. Снятие галочки теперь действует на оба рантайма (под lmxxf сеть
  пересобирается: фриз примерно на 1 с); под lmxxf теперь также действуют Structure intensity и
  Character structure.
- **Больше деталей на лицах** (новое в 0.3.5.6, оба рантайма, всегда включено) — пока Character structure следует за
  Structure intensity (галочка по умолчанию), лица и кожа получают в 1.5 раза больше структуры, чем сцена, но не больше
  4 (с Full Model Look: 2.00 -> 3.00); без дополнительного прохода и без дополнительной нагрузки. Character structure,
  заданный вами самими, всегда имеет приоритет, а серое значение в меню показывает поднятое число.
  `[DlssNr] AmdFaceDetail=false` (только в ini) выключает это.
- **Game exposure** (Image look > Exposure and highlights, `[DlssNr] AmdUseGameExposure = auto | 1 | 0`, оба
  рантайма) — с 0.3.5.6 его пункты называются **Auto / On / Off**. Auto использует собственное значение яркости игры,
  когда игра его публикует; On всегда передаёт его сети; Off никогда не передаёт, и управление берёт на себя
  собственная автоэкспозиция рантайма — попробуйте Off, если NR делает игру слишком тёмной или слишком светлой.
  Действует со следующего кадра модели.
- **Anti-halo** (Image look > Appearance filter, `[AmdLook] AntiHalo`, 0..1, по умолчанию 0.901; до 0.3.5.6
  назывался Halo protection, ключ тот же) — ограничивает правку фильтра рядом с резкими границами, чтобы не возникало
  светлого или тёмного ореола; чем выше, тем безопаснее края и чуть мягче детали рядом с ними. Нужно, чтобы Effect mix
  фильтра был больше 0.
- **Генерация кадров (FG) в новом ini выключена**, и включается она в пять шагов: FG Input и FG Output на вкладке
  Frame Gen (например, "DLSSG via Streamline" в игре с генерацией кадров DLSS, и XeFG), **Save Settings**, полный
  перезапуск игры, включённая **собственная** генерация кадров игры, затем отмеченная галочка **Active** в разделе
  Frame Generation. С 0.3.5 вкладка и лог называют недостающий шаг. Полный список, с тем, что выключить в игре, — в
  FAQ ниже («Генерация кадров: нет прироста FPS?»).
- **Мультикадровая генерация XeFG** — от 3X до 6X встроено и включено по умолчанию (`XeFG\UnlockMFG`),
  как для копии OptiScaler, так и для собственной копии игры. **Удалите `XeFGUnlock.asi`** из `OptiScaler\plugins`,
  если он у вас остался: две копии одного и того же патча приводят к вылету игры.
  **До 10X — включается вручную** (только в играх на D3D12): задайте *XeFG ceiling (restart)* в разделе FG Output
  на вкладке Frame Gen (4X, 6X по умолчанию, 8X или 10X; `[XeFG] MaxInterpolatedFrames`), перезапустите игру,
  затем выберите множитель в списке MFG. Выше 6X нужен собственный провайдер XeFG от OptiScaler с включённым
  Extra pacing; копия XeSS 3, поставляемая с игрой, остаётся максимум на 6X. Для 10X нужен дисплей 360 Гц+ и
  ограничение кадров на уровне частоты обновления / 10; задержка высокая, а провайдер резервирует примерно
  на 128 МиБ больше VRAM в 4K. 7X-10X в игре пока не подтверждены: тестеры, пришлите, пожалуйста, `OptiScaler.log`.
- **FSR Ray Regeneration** — на RX 9000 (RDNA 4); на RX 7000 (RDNA 3) как preview, включённый по умолчанию, с AMDNR Ray Denoiser в роли денойзера (см. ниже); только в играх с DLSS Ray Reconstruction (Cyberpunk 2077,
  Alan Wake 2), при этом игра должна работать на DLSS (spoofing включён), а трассировка лучей и Ray
  Reconstruction должны быть включены в её собственных настройках. Тогда Neural Rendering выполняется после
  него, на его выходе, что обходится дороже: снизьте NR resolution, если FPS проседает. С 0.3.5 его настройки
  находятся на собственной вкладке **Ray Regeneration**, сразу после Upscaling, которая рисуется, пока в игре работает
  Ray Regeneration; с 0.3.5.3 на вкладке Neural нет строки Ray Regeneration, только оранжевая строка под рантаймом, когда Ray Regeneration выключен в игре или не смог запуститься на этой видеокарте. Строка **Denoiser backend** на этой вкладке (`[FSR-RR] RrBackend` = auto / amd / amdnr / off) предлагает Automatic (AMD FSR Ray Regeneration на RX 9000, AMDNR Ray Denoiser (preview) на всех остальных видеокартах), AMD FSR Ray Regeneration, AMDNR Ray Denoiser (preview) и Off (the game's own); первые три переключаются прямо во время игры, а Off сообщает игре, что Ray Reconstruction не поддерживается, и тогда она оставит свой денойзер (при следующем запуске игры). В игре на **Vulkan** Ray Reconstruction — "not
  supported", так задумано (денойзер работает на D3D12), и вкладка об этом говорит. **Профиль path-traced** (меньше
  зерна на лицах при path tracing) с 0.3.3.1 включается вручную: отметьте его там, чтобы попробовать в Resident Evil
  Requiem или PRAGMATA. На той же вкладке — сила bias mask и **сглаживание кожи** (экспериментально, для игр, которые
  предоставляют SSS guide; по умолчанию выключено, но в Resident Evil Requiem с 0.3.3.2 включено по умолчанию);
  ползунки временной настройки — в *More Ray Regeneration options*, а отладочный вид RR и показатель шума (зерно на
  входе и на выходе, мерцание при неподвижной камере) — в собственном блоке Diagnostics вкладки. На RX 7000 (RDNA 3)
  Ray Regeneration предлагается как preview (0.3.5.1; в 0.3.5 по умолчанию не предлагался): игра может включить Ray
  Reconstruction, и настройки Ray Regeneration показываются, а шум убирает AMDNR Ray Denoiser (preview), и на APU RDNA 3 / 3.5 тоже (AMD FSR Ray Regeneration сделан для RDNA 4); страница Ray Regeneration говорит, что работает. Флажок на вкладке
  Upscaling **Preview: Ray Regeneration on this card (restart)** (с пометкой «preview - on by default») по умолчанию
  включён; снимите его или задайте `[FSR-RR] FfxDenoiserAllowPreRdna4=false`, и игра останется со своим денойзером.
  RX 6000 и более старые карты получают его только по желанию, с `[FSR-RR] FfxDenoiserAllowPreRdna4=true` (вкладка Upscaling: **Offer Ray Regeneration on this GPU (restart)**, с пометкой "preview"), тоже с AMDNR Ray Denoiser. **Резкость после RR**
  (0.3.4.1): когда игра не передаёт значение резкости, AMDNR в Windows добавляет после RR резкость 0.25 (в Linux /
  Proton — 0); чтобы выключить: Image > Sharpness, отметьте Override, ползунок на 0. С 0.3.4.2 это число - отдельный ключ ini,
  `[Sharpness] RrDefaultSharpness` (то же значение по умолчанию 0.25): поставьте там 0.15, 0.10 или 0, не трогая
  Override, а значение, которое ваш ini хранит в `[Sharpness] Sharpness` при выключенном Override, отмечается в меню
  как ожидающее.
- **AMDNR Screen-space GI by 3zwr1** (по умолчанию выключено; Neural > Screen-space GI или `[AmdGi] Enabled=true`) — собственный отражённый свет и затенение окружения (ambient occlusion) в экранном пространстве от AMDNR, по глубине игры, до NR, апскейлера и интерфейса; работает с включённым и выключенным NR; Low / Medium / High / Ultra (Auto по видеокарте), около 0.6 мс на High при рендере 1080p на RX 9070 XT (измерено). Это экранное пространство: света из-за пределов экрана нет. См. `CHANGELOG.md`.
- **Model E / Model L** (вкладка Upscaling, новое в 0.3.5.6) — экспериментальные варианты апскейлера от других
  авторов, которые скачивает AMDNR Launcher; Model L работает с lmxxf или с выключенным NR. См. «Model E и Model L».
- **Save report** (Neural > Diagnostics или Advanced > Logging) — один zip со всеми логами и ini-файлами для баг-репорта; см. «Если не
  работает» выше.

## Если что-то пошло не так

`OptiScaler.log` появляется в папке игры. Приложите его в `#bug-report` и укажите игру и
видеокарту; **Save report** (Neural > Diagnostics или Advanced > Logging) упакует его вместе со всем остальным. AMD-бэкенд также пишет
`amd_presr.log` и `amd_bridge.log` — именно они полезны, когда сбоит конкретно нейронный проход. Логи трёх
последних сессий сохраняются как `OptiScaler.previous.<exe>.log` (самый новый), `OptiScaler.previous-1.<exe>.log` и
`OptiScaler.previous-2.<exe>.log` (`[Log] KeepPreviousLogs`; 1 оставляет только один, как раньше). После вылета
приложите и их: в новом логе тогда будет "no clean exit recorded" (с 0.3.4 — уже не после обычного выхода).

**NR frames 0/s, а вкладка Neural или `amd_presr.log` сообщает, что DLL прохода — это сборка, с которой этот
AMDNR не работает?** Ваши `dlssnr_amd_pass1..3.dll` — сборка danielblnc, которую этот AMDNR не знает (в сети
попадался набор 0.2.16), или одного из трёх файлов не хватает. Начиная с 0.3.3.2 вкладка Neural называет файл
и его версию и подсказывает, что делать. Используйте рекомендованный рантайм, все три DLL прохода из одного
и того же zip: `v0.6.0-Runtime.zip` из Alpha0.3.5.5R4 (176,366,023 байт, SHA256 начинается с `d2bb1702`; на RX 9000,
RX 7000 и RX 6000); `v0.5.1-Runtime.zip` (Alpha0.3.5), `v0.5.0-Runtime.zip` (Alpha0.3.4.2; 149,550,553 байт, SHA256
начинается с `7a49ab0e`), `v0.4.3-Runtime.zip` (Alpha0.3.4.2 и Alpha0.3.4.1; 116,484,918
байт, SHA256 начинается с `07dd7774`), `v0.4.1-Runtime.zip` и `v0.4.0-Runtime.zip` (Alpha0.3.4.1) по-прежнему
принимаются (`dlssnr_amd_pass1.dll` в `v0.4.1-Runtime.zip` весит 9,916,928 байт, SHA256 начинается с
`823063eb`; в `v0.4.0-Runtime.zip`: 10,027,008 байт, `d62be3d8`).
Поддерживаемые сборки: 0.2.17, 0.3.0, 0.3.1, 0.3.2, 0.3.3, 0.4.0 и zip рантаймов, названные выше, вплоть до 0.6.0.
Не устанавливайте собственный установщик danielblnc и его
`dxgi.dll` / `version.dll` / `winhttp.dll` рядом с AMDNR: AMDNR уже запускает его рантайм. **Сборку danielblnc новее
0.6.0 этот релиз не запускает:** вкладка Neural называет файл и его версию и сообщает об этом. С 0.6.0, 0.5.1, 0.5.0,
0.4.3, 0.4.1 и 0.4.0 настройки, доступные только с danielblnc (Network style, Tone curve, Black lift, Game exposure,
Fast mode), работают; с 0.3.5.5R4 `Async=1` в `dlssnr_on_amd.ini` выполняется в режиме того же кадра
(`[DlssNr] AmdDanielAsync=true` пропускает его как есть; см. «Что лежит в архивах»).

**danielblnc: NR остановился после нескольких «таймаутов», или на экране было написано, что драйвер дисплея сбросил
видеокарту?** Исправлено в 0.3.5.6 (проверено в Silent Hill 2). Причина найдена: когда в папке игры лежали файлы
Model L, рантайм danielblnc получал собственную копию HIP из Model L, и его ожидание так и не видело, что задание
завершилось. Теперь AMDNR даёт HIP из драйвера всем, кто его вызывает, кроме Model L. Ожидание, которое сдаётся,
теперь так и называется в отчёте и больше не выключает Neural Rendering; сброса драйвера не было, и этот текст убран; а
заметка "runtime failed", которую читает Doctor в лаунчере, записывается только после настоящего сбоя. Рантайм
danielblnc работает в паре с Model E; для Model L используйте lmxxf.

**Вы выбрали FSR 3 / FSR 4, а в игре работал FSR 2.1.2?** С 0.3.5.6 неудавшийся или не готовый выбранный апскейлер
(Model E, Model L или другой) должен оставлять ваш собственный выбор FSR (FSR 4 / FSR 3.1), а не откатываться к
FSR 2.1.2 (D3D12); FSR 2.1.2 работает, только если вы выбрали его сами или если не может работать никакая другая
библиотека FSR, и лог об этом сообщает. В некоторых играх на D3D11 и Vulkan неудавшийся апскейлер всё ещё может
откатиться к FSR 2.2. Если вы всё же это видите, пришлите zip отчёта.

**lmxxf ничего не делает или сразу останавливается на ПК со встроенной графикой?** Исправлено в 0.3.3.2.
На десктопном Ryzen с включённой встроенной графикой, на ноутбуке с APU AMD и Radeon или на ПК с двумя
видеокартами AMD видеокарта, на которой идёт игра, часто не является HIP-устройством 0. Тогда lmxxf падал
на первом же кадре (`hipErrorInvalidHandle (400)`, затем "session is poisoned" в `lmxxf_backend.log`) и
оставался выключенным. Замените и `OptiScaler.dll` (файл, который вы переименовали, например `dxgi.dll`), и
`LmxxfNrRuntime.dll` файлами из 0.3.3.2 или новее. На таком ПК это пока не тестировалось: если lmxxf всё равно
останавливается, вкладка Neural теперь объясняет причину; пришлите `lmxxf_backend.log` и `amd_bridge.log`
(в нём перечислены HIP-устройства).

**ПК со встроенной графикой и Radeon (десктопный Ryzen с включённой встроенной графикой или ноутбук): NR никогда не
запускается, а вкладка Neural или строка GPU называет встроенную графику?** Нейронный проход AMDNR работает на той
видеокарте, на которой рисует игра. Если Windows запустила игру на встроенной графике, NR на вашей Radeon не работает
вовсе. Назначьте игре дискретную видеокарту: Параметры Windows > Система > Дисплей > Графика, добавьте `.exe` игры,
Параметры, Высокая производительность; затем перезапустите игру и проверьте строку GPU в Neural > Diagnostics — она
называет адаптер, на котором работает NR (в `OptiScaler.log` есть строка `AMD neural: NR runs on ...`, когда этот
адаптер не является основной видеокартой). Замечено в Starfield на десктопном Ryzen. С 0.3.5 строка на вкладке
Neural говорит, какой из трёх случаев перед вами: рантайма ещё нет, NR работает **на встроенной графике** (APU,
который принимает рантайм, например Radeon 780M рядом с видеокартой Radeon: NR работает там, намного медленнее, чем
на видеокарте) или рантайм работает на другом адаптере; а `amd_bridge.log` один раз перечисляет все адаптеры.

**Строка состояния lmxxf показывает `c32w=off:nofile` на RX 9070 / 9070 XT?** Старая папка
`DLSS5-AMD\native-game-tiled-assets` рядом с `.exe` игры (осталась от прежней установки lmxxf) используется
вместо `LmxxfNrRuntime.pak`. В ней нет ядер c32w, поэтому lmxxf работает с прежней скоростью. Удалите папку
`DLSS5-AMD` или переименуйте её: в pak есть всё, что нужно lmxxf. `LmxxfNrRuntime.pak` старше 0.3.3.2 даёт то
же состояние; замените его файлом из этого релиза.
`fk=fff-` в той же строке означает то же самое (старый pak или отдельная папка): lmxxf всё равно работает,
с прежней скоростью.

**danielblnc: стиль NR всё ещё меняется, когда NR resolution уходит от 100%?** С 0.3.4 по 0.3.5 это всё ещё
открыто, и значение по умолчанию не меняется. При 100% Residual strength 0.99 даёт 99% от 1.00 (исправлено в 0.3.3.2); вне
100% (в том числе на шагах Dynamic NR и в пресетах Balanced / Performance) strength, limit и edge fade по-прежнему
действуют на весь результат, поэтому вид может меняться. В 0.3.4 добавлено A/B-сравнение, чтобы найти правильное
исправление: Neural > Diagnostics > **Edit shaper (A/B, not saved)** с Literal, F1 и F2, а также Only below 100% и
Carry cap (только danielblnc; Save Settings это не сохраняет; ключи в ini — `[DlssNr] AmdEditShaper`,
`AmdEditShaperLimit`, `AmdEditShaperScope` и `AmdEditShaperCarryCap`). Если какой-то из них делает 85% похожим на
100% в вашей игре, сообщите нам в Discord со скриншотами. lmxxf это не затрагивает.

**Меню открывалось и закрывалось дважды от одного нажатия, или клавиатура и мышь переставали работать на всём
рабочем столе, пока меню было открыто (Assetto Corsa)?** Исправлено в 0.3.4: повторное нажатие клавиши меню или NR
в течение 400 мс игнорируется (`[Hotfix] MenuToggleDebounceMs`, 0 = прежнее поведение), а при открытом меню
низкоуровневый хук клавиатуры или мыши игры пропускается, но клавиша всё равно доходит до Windows
(`[Hotfix] MenuLowLevelHookPassThrough=false` = прежнее поведение). В Assetto Corsa пока не подтверждено: если это
повторится, пришлите zip отчёта.

**Меню открывалось само на окне выбора рантайма, клики ничего не делали, или клавиша меню скрывала его только пока
удерживалась (Assetto Corsa)?** Исправлено в 0.3.4.2: клавиша меню открывает или закрывает его один раз за физическое
нажатие (опоздавшее сообщение клавиши игнорируется), клики и клавиши меню короче одного кадра воспроизводятся, окно
выбора рантайма отвечает на `1` / `2` / `Enter` / `Esc` и на X в своей строке заголовка, а закрытие меню считается за
"Decide later"; окно выбора больше не открывает меню само. Игроком в Assetto Corsa пока не подтверждено:
если это повторится, пришлите zip отчёта. Чтобы вернуть клавишу меню и клики из 0.3.4.1:
добавьте строку `DiagInputHooksSkip=presslatch,clickreplay` в раздел `[Hotfix]` своего `OptiScaler.ini` сами (без
нового ключа; в поставляемом ini она только описана в комментарии).
0.3.5 добавляет для Assetto Corsa две вещи: AMDNR отходит в сторону, если в папке игры лежит чужой `nvngx.dll`, и
защищает создание устройства D3D11On12, а игра на DX11, которая никогда не выводит кадры через D3D12, получает
загрузочную (bootstrap) очередь D3D12 для нейронного прохода (`[DlssNr] AmdBootstrapQueue`, auto). Игроком в Assetto
Corsa пока не подтверждено.

**Uncharted: Legacy of Thieves Collection вылетала через несколько секунд после запуска на RX 9000 с включённым Neural
Rendering?** Исправлено в 0.3.5: игра выполняет свою работу на маленьких файберах по 192 КиБ, а первая инициализация
HIP (драйвер компилирует свои вспомогательные ядра внутри игры) переполняла этот стек на первом кадре NR. Первое
обращение нейронного моста к HIP теперь выполняется на собственном большом стеке (`[DlssNr] BigStackCall`, auto).
Если для 0.3.4.2 вы ставили там `[DlssNr] Enabled=false`, включите его обратно. Игроком на RX 9000 пока не
подтверждено: если это повторится, пришлите zip отчёта.

**Игра с динамическим разрешением (The Last of Us Part II) мерцает с включённым Neural Rendering?** Исправлено в
0.3.5: игра меняла свой размер рендера сотни раз в минуту, и каждый шаг пересобирал сеть и сбрасывал её историю. Шаг,
который остаётся в пределах уже выделенной памяти, теперь удерживается (без стабилизации, без прогрева, без сброса
истории, оба рантайма); больший кадр или реальное уменьшение по-прежнему приводят к перевыделению. Строка статистики
в отчёте считает удержанные шаги. В этой игре пока не подтверждено.

**Генерация кадров: нет прироста FPS или вечное "restart the game"?** Почти во всех отчётах генерация кадров просто
не была включена — выключена, а не сломана. Она включается в пять шагов, и с 0.3.5 вкладка Frame Gen и лог называют
тот, которого не хватает:

1. Вкладка Frame Gen: выберите **и** FG Input, **и** FG Output. Игра на DX12 с собственной генерацией кадров: вход —
   её DLSS FG или FSR 3.1 FG (игры с FSR 3.1 FG: "FSR 3.1 FG", а не "FSR 3.0 FG"); в игре вообще нет FG: FG Input =
   OptiFG (Upscaler), HUD fix включён. DX11: только OptiFG. Vulkan: выхода FSR FG / XeFG нет (используйте
   собственную генерацию кадров игры).
2. **Save Settings**.
3. **Полностью закройте игру и запустите её снова** — FG нельзя включить прямо во время игры.
4. В собственных графических настройках игры **включите** её генерацию кадров: DLSS Frame Generation (с DLSS в
   качестве апскейлера) для входа DLSSG, генерацию кадров FSR (с FSR) для входа FSR 3.1 FG.
5. Снова откройте меню, вкладка Frame Gen, отметьте **Active** в разделе Frame Generation. Пока эта галочка не
   отмечена, ничего не генерируется (XeFG может попросить ещё один перезапуск).

Затем **выключите** в игре: эксклюзивный полноэкранный режим (XeFG нужен режим окна без рамки), V-Sync и ограничения
кадров (или ограничьте на удвоенном базовом FPS), а также собственную генерацию кадров XeSS в игре, если она есть
(один генератор кадров на окно; игра, которая загружает свой XeSS FG, получает пометку на вкладке). Нет прироста FPS
= FG выключена — лог пишет `... Enabled is off ...: no frames are generated. Frame generation off, not broken.`; FPS
вдвое меньше = ограничение или V-Sync сдерживает сгенерированные кадры. Если всё равно не работает, нажмите **Save
report** после сбоя и выложите zip, указав игру, выбранную пару, какая опция генерации кадров в игре была включена,
окно без рамки или полный экран, HDR включён или выключен и что вы увидели. Полный FAQ закреплён в канале поддержки
в Discord.

**Другие моды (RED4ext, Cyber Engine Tweaks для Cyberpunk 2077) или ReShade рядом с AMDNR?** С 0.3.5 отчёт и лог
называют прокси-загрузчики других модов (`Mod loaders:` в `report.txt`; RED4ext — это `winmm.dll`, Cyber Engine
Tweaks — `version.dll` через ASI-загрузчик) и предупреждают, когда AMDNR занимает имя известного загрузчика этой игры,
не передавая ему загрузку по цепочке. AMDNR Launcher никогда не забирает и не перемещает файл загрузчика: он выбирает
другое имя прокси (Cyberpunk 2077: `dxgi.dll`), а его Doctor называет любой загрузчик, который отодвинул в сторону
прежний INSTALL (`AMDNR_backup`). ReShade рядом с AMDNR определяется по ресурсу версии модуля или по экспортам
дополнений (add-on) ReShade, никогда по имени файла, и называется в отчёте и в логе
(`[Game] ReShade detected: <module>`); ничего не загружается, не перехватывается и не блокируется, а совместное
использование D3D12-устройства обоими спроектировано, но ещё не сделано.

**`No HIP adapter matches D3D12 LUID` на вкладке Neural или в `amd_bridge.log`?** С 0.3.5 эта строка называет обе
стороны — D3D12-адаптер игры (имя, LUID), каждое HIP-устройство (порядковый номер, имя, gfx, LUID) — и вероятную
причину с тем, что делать: игра работает на встроенной графике или другой видеокарте (Параметры Windows > Система >
Дисплей > Графика: назначьте игре дискретную видеокарту), рантайм HIP без идентификации (лишний `amdhip64_7.dll` рядом
с игрой: удалите его), HIP-устройств нет вовсе (установите фирменный драйвер AMD Adrenalin), та же видеокарта под
другой идентификацией или адаптер не от AMD. Оба рантайма пишут одинаковый текст.

**Игра на Vulkan (Indiana Jones and the Great Circle) останавливается при запуске с ошибкой "Could not create
the Vulkan device (VK_ERROR_EXTENSION_NOT_PRESENT)"?** Исправлено в 0.3.2: унаследованный нейронный путь
NVIDIA запрашивал у драйвера AMD два расширения устройства, которые есть только у NVIDIA. Игры на Vulkan
попадают в нейронный проход через мост D3D12 от OptiScaler (см. «Требования»).

**lmxxf вешал игру на Vulkan на первом кадре NR?** Исправлено в 0.3.3; при старте NR ожидайте один
фриз примерно на 1 с. Если сессия на Vulkan когда-нибудь остановится до первого ответа lmxxf, при
следующем запуске будет работать рантайм danielblnc, а вкладка Neural объяснит почему; нажмите там
**Retry lmxxf** (это удаляет `lmxxf_vk_launch.pending` рядом с `OptiScaler.dll`), чтобы снова попробовать lmxxf.

**danielblnc подвисал на несколько секунд, а затем отключал NR в игре на Vulkan (Indiana Jones) с 2-3 Neural
passes?** Исправлено в 0.3.3: в играх на Vulkan он выполняет 1 проход, а его ожидание 80 мс после отправки
(post-submit) убрано. Первый кадр NR в сессии по-прежнему даёт паузу около 5 с; подсказка под выбором рантайма
объясняет соответствующие строки лога. Тестерам: `[DlssNr] AmdVkLateCopyWait=true` (экспериментально, по
умолчанию выключено, в игре пока не проверено) должно убрать эту паузу; присылайте `OptiScaler.log`,
`amd_presr.log` и `dlssnr_on_amd.log`.

**Потребление RAM у lmxxf росло всё время, пока работал NR?** Исправлено в 0.3.3 (было около 45 ГБ в час
при 60 кадрах NR в секунду). Что осталось: danielblnc удерживает VRAM для каждого нового размера NR больше
примерно 1 Мп (в 0.3.3.2 его размеры вне 100% округляются до 64 px, так что таких размеров совсем немного);
с danielblnc перезапускайте игру после множества изменений. Начиная с 0.3.3.2 lmxxf больше не удерживает около
97 МБ на каждое изменение NR resolution или режима DLSS: он создаёт буферы сети один раз для каждого размера
сети и затем использует их повторно (на каждое изменение остаётся лишь небольшой остаток — около 10-25 МБ VRAM).

**Игра на Streamline не запускается с ошибкой slInit 0x18 (замечено в NBA 2K27 на AMD)?** В 0.3.3 закрыт
один из путей, которым её могли вызывать хуки OptiScaler на плагины Streamline, но не подтверждено, что
причина в NBA 2K27 именно в этом. В `OptiScaler.log` теперь пишутся строки `slInit returned ...` и `[SLINIT]`:
пришлите лог вместе с отчётом.

**Не можете найти настройки Ray Regeneration?** С 0.3.5 они на собственной вкладке **Ray Regeneration**, сразу после
Upscaling, которая рисуется, пока в игре работает Ray Regeneration (и остаётся до конца сессии, если он уже
работал); с 0.3.5.3 на вкладке Neural нет строки Ray Regeneration. Пока он не работает, вкладка не рисуется; если Ray Regeneration выключен в этой игре или не смог запуститься на этой видеокарте, об этом говорит оранжевая строка под рантаймом на вкладке Neural. На RX 7000 и APU RDNA 3 / 3.5 Ray Regeneration предлагается как preview, включённый по умолчанию, а шум убирает AMDNR Ray Denoiser (preview) (AMD FSR Ray Regeneration сделан для RDNA 4); `[FSR-RR] FfxDenoiserAllowPreRdna4=false` (или снятый флажок на вкладке Upscaling **Preview: Ray Regeneration on this card (restart)**) выключает preview, и игра остаётся со своим денойзером. На RX 6000 и старше он по умолчанию не предлагается: флажок на вкладке Upscaling **Offer Ray Regeneration on this GPU (restart)** (`[FSR-RR] FfxDenoiserAllowPreRdna4=true`) включает его, с AMDNR Ray Denoiser (preview). Чтобы он
заработал, в графических настройках самой игры: выберите **DLSS** как
апскейлер (не FSR и не XeSS), включите **трассировку лучей** или path tracing и включите **Ray Reconstruction**
(DLSS-RR); на вкладке Upscaling тогда будет написано "FSR Ray Regeneration". Что менять при какой проблеме — в
руководстве по настройкам Ray Regeneration
**RR-BEST-SETTINGS.md** (его нет в zip).

**Ray Regeneration выглядит зернистым или шумным?** Сначала судите о нём с **выключенным Neural Rendering**
(снимите галочку **Enable Neural Rendering** наверху вкладки Neural, нажмите Home во время игры или поставьте
`[DlssNr] Enabled=false`): нейронный проход выполняется после Ray
Regeneration, на его выходе, поэтому скриншот с включённым NR ничего не говорит о денойзере. Затем, по типу зерна —
ползущее зерно в неподвижной сцене, яркие точки, зерно на лицах, шлейфы за движущимися персонажами — настройки, которые
стоит попробовать, собраны в том же руководстве, **RR-BEST-SETTINGS.md**. **В 0.3.4.2 не изменилось ни одно
значение денойзера или резкости по умолчанию**: числа те же, что в 0.3.4.1. Изменилось другое: резкость, которую
AMDNR добавляет после Ray Regeneration, теперь отдельный ключ ini, `[Sharpness] RrDefaultSharpness` (то же значение
по умолчанию 0.25), так что 0.15, 0.10 или 0 - это правка ini, а не новая сборка. Проверьте свой ini, прежде чем гоняться за
зерном ползунком резкости: значение в `[Sharpness] Sharpness` ничего не делает, пока `OverrideSharpness` выключен, и
начинает действовать в тот момент, когда вы отмечаете **Override** в меню, - поэтому Image > Sharpness теперь
помечает его ("ini Sharpness 1.00 waits for Override"). Две вещи, которые мы не станем замалчивать:
часть зерна — это собственная выборка лучей игры (денойзер AMD не предназначен для того, чтобы исправлять шум,
приходящий скоррелированным, а игра, предлагающая DLSS Ray Reconstruction, выключает свой денойзер и передаёт нам сырой
сигнал), а у зерна, которое ползёт в неподвижной сцене, на нашей стороне структурная причина, которую ни один ползунок
не убирает полностью. Это известная проблема. 0.3.5 выражает её в числах: блок Diagnostics на вкладке Ray
Regeneration показывает зерно на входе и на выходе и мерцание при неподвижной камере (измеряется, пока вкладка
открыта), а строку **Denoiser backend** на этой вкладке можно поставить в Off — это сообщает игре, что Ray
Reconstruction не поддерживается, и она оставляет свой денойзер (после перезапуска). С 0.3.5.3 та же строка предлагает и собственный денойзер AMDNR — AMDNR Ray Denoiser (preview), который Automatic выбирает на всех видеокартах, кроме RX 9000.

**Ray Reconstruction в игре включён, но вкладка Neural пишет "Ray Regeneration is off in this title"?**
Игра не отдаёт то, что нужно FSR Ray Regeneration: её плагин DLSS передаёт пустые матрицы камеры (Satisfactory),
которые Ray Reconstruction от NVIDIA считает необязательными, а FSR Ray Regeneration без них не работает. Вместо
него работает апскейлинг FSR, а NR занимает своё обычное место до SR; вкладка Upscaling сообщает то же самое. С
0.3.4 в игре на Unreal с такой сигнатурой он остаётся выключенным до конца сессии. Выключите Ray Reconstruction в
игре и верните собственные настройки денойзера движка.

**Игра на движке Ubisoft Anvil (AC Black Flag Resynced, Shadows, Mirage) показывает "DX12 Error 0x80070057"?**
В этих играх есть собственная генерация кадров XeSS. С 0.3.5 вкладка Frame Gen показывает там совет (оставьте
собственный XeSS FG игры выключенным, иначе два генератора будут делить одно окно), а выход XeFG от AMDNR при этом
продолжает работать; самый простой путь — собственная опция XeSS FG в игре при выключенной генерации кадров AMDNR.
Если ошибка всё равно появляется, задайте `[FrameGen] Enabled=false` и `[fakenvapi] ForceXeLL=false` и отправьте
отчёт с логом.

**The Last of Us Part I вылетает при запуске?** Это собственная инициализация Streamline в игре, известная
проблема OptiScaler: переименуйте `sl.common.dll` в папке игры в `sl.common.dll.bak` и выберите
**FSR 3.1** в настройках игры вместо DLSS.

Полные заметки по каждой версии: `CHANGELOG.md` (в zip и в репозитории).

## AMDNR Launcher

**AMDNR Launcher** (новое в 0.3.4) — программа для Windows 10 / 11, которая может работать и под Proton в Linux
(экспериментально, нами пока не проверено: см. «Linux / Proton»). Он устанавливает и обновляет AMDNR для каждой
игры: находит ваши игры (Steam, Epic, приложение Xbox, Ubisoft Connect, приложение EA, GOG, Rockstar, Battle.net и
Amazon Games), подбирает имя DLL, скачивает сборку и выбранный вами рантайм danielblnc (а если вы их выбрали — ещё и
Model E и Model L из собственных релизов их авторов), проверяет каждую установку
своим Doctor, запускает AMDNR Anywhere для игр без собственного апскейлера (PLAY ANYWHERE) и обновляется сам.
Скачайте `AMDNR-Launcher.exe` — AMDNR Launcher из последнего релиза — со страницы релизов:
<https://github.com/3zwr1/AMD-NR---OptiScaler/releases>

**Новое в Launcher 0.3.5.25** (в релизе Alpha0.3.5.6; сначала он обновляет себя, затем ваши игры):

- **SR model** в GAME SETTINGS игры: Auto / Model E / Model L (см. «Model E и Model L»). При первом выборе модели
  лаунчер показывает сведения о ней (disclosure; ACCEPT / Cancel, по умолчанию — Cancel); затем он скачивает её
  файлы из собственного релиза автора с проверкой по хешу. Model L работает в паре с рантаймом lmxxf (или с

AMDNR 0.3.5.7 Public View - lmxxf 0.4.4 integration

Kien/lmxxf (MIT), integrated with AMDNR settings and own host lifecycle.
Includes Model A/B, C32 W16h, C512 W16, paired byte edges, variable Small

New in this complete local package:
